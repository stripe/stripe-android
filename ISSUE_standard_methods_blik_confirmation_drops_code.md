The entered code has no end-to-end confirmation carrier in the current Android/Checkout Client integration.

Elaboration: BlikDefinition collects BlikCode; form conversion represents it as PaymentMethodOptionsParams.Blik, and PaymentSelection.toConfirmationOption carries it as optionsParams. CheckoutSessionConfirmationInterceptor.createConfirmParams copies createParams but never optionsParams. ConfirmCheckoutSessionParams has no option field and never serializes payment_method_options. The missing transport also exists on the server: [authoritative backend contract](bug-bash/standard-methods/BLIK_BACKEND_CONTRACT.md) at5446557e0835417a195f441f35a90963d404f503 shows Checkout Client ConfirmParams::MethodParams accepts no payment_method_options/confirmation_token, and PaymentPageConfirmRequest forwards neither. Thus adding a client field alone is not established as a fix. This is a concrete failure of an offered/documented method, not an intentionally excluded method inferred from source absence. The [mobile test contract](bug-bash/docs-driven/STANDARD_METHODS_DOCS_EXCERPTS.md) includes BLIK; its invalid/expired/delayed/timeout simulations cannot be reached through this flow because even the successful-code control fails before bank authentication. No unsupported parameter injection, backend gate change, legacy confirmation substitution, or production fix was used.
