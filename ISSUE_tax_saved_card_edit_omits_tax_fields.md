Elaboration: DefaultEmbeddedUpdateScreenInteractorFactory passes only metadata.billingDetailsCollectionConfiguration.address to DefaultUpdatePaymentMethodInteractor. BillingDetailsForm hardcodes requiresBillingAddressForAutomaticTax=false when choosing cardBillingAddressCollectionMode; automatic mode therefore hides US street/city/state, unlike the new-card automatic-tax form. Save updates the real PaymentMethod successfully. Selecting the edited saved card synchronizes billing tax and reloads Checkout state. DefaultPaymentMethodFilter requires hasSufficientBillingDetailsForAutomaticTax; automaticTaxRequiredFields(US) includes Line1,City,State,PostalCode, so this newly saved card fails local filtering. The backend still returns it and calculates tax, distinguishing the SDK's unusable saved-card state from backend removal or a tax service rejection. The missing fields, disappeared card, and failed confirmation are one root cause. This reproduces the historical behavior described in the bug-bash skill, whose old report is absent in this checkout; it is not a separate tax-rate correctness claim or the existing email-selection defect.
