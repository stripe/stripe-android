Summary: A customer opening saved payment methods in Checkout Elements receives an accessibility label of "Unknown ending in 8 4 3 1" for a supported American Express card. The row displays the correct Amex icon, but its exposed content description loses the card brand, making the saved instrument harder to identify through accessibility services.

Repro: Use the CheckoutElementsController example at `cf7dd4b99965a4e754abdadacf4f337e764f6e6a` with a test customer containing an attached `tok_amex` PaymentMethod. The actual returned card has `brand=amex`, `display_brand=american_express`, and last4 `8431`. In the captured run it has `allow_redisplay=unspecified`, so create a `mobile_elements` EUR session with `saved_payment_method_options.allow_redisplay_filters=[always,limited,unspecified]`; allow card, SEPA and Bancontact, with ordinary all-brand acceptance and tax off. Open the native saved-method selector through View more. The Amex row's UIAutomator `content-desc` is "Unknown ending in 8 4 3 1 ", while Visa and Mastercard expose their names. `bug-bash/lpms/native_probe.py` with fresh `LPMS_NATIVE_STATE` and physical `ANDROID_SERIAL` reproduces this via `serve`, `prepare mixed`, native Create Checkout Session, then View more; finish with `restore` and stop the relay. The defect also reproduced with Visa disallowed. No TalkBack setting was changed and actual speech was not tested.

Test: On Pixel 6a/API 36, the unchanged debug SDK produced the actual [saved-method screenshot](bug-bash/lpms/native/mixed-saved-all.png) and [accessibility XML](bug-bash/lpms/native/mixed-saved-all.xml), with matching [real backend inventory](bug-bash/lpms/native/mixed-initial.json). The [Visa-disallowed screenshot](bug-bash/lpms/native/no-visa-saved.png) and [XML](bug-bash/lpms/native/no-visa-saved.xml) reproduce the same label. The evidence-only [LpmNativeCardDescriptionBashTest.kt](bug-bash/lpms/LpmNativeCardDescriptionBashTest.kt) minimizes those real card fields through `PaymentMethodJsonParser` and `DisplayableSavedPaymentMethod.getDescription()`. `captured Amex exposes its supported brand name` fails as expected: expected `American Express ending in 8431`, actual `Unknown ending in 8431`. Captured Visa plus seven existing formatter controls pass: [8 passed, 1 expected failure](bug-bash/lpms/native/jvm-description-results.json). Copy the evidence test into `paymentsheet/src/test/java/com/stripe/android/paymentsheet/`, run `./gradlew :paymentsheet:testDebugUnitTest --tests 'com.stripe.android.paymentsheet.LpmNativeCardDescriptionBashTest' --tests 'com.stripe.android.paymentsheet.DisplayableSavedPaymentMethodTest'`, then remove that copy. The temporary source was removed after validation; no fix is included.

Elaboration: The real Checkout customer inventory returns `brand=amex` and `display_brand=american_express`. `PaymentMethodJsonParser` correctly parses the former as `CardBrand.AmericanExpress` and retains the latter string. `DisplayableSavedPaymentMethod.brandDisplayName()` maps a non-null displayBrand through `CardBrand.fromCode()` and falls back to card.brand only when displayBrand is null. `CardBrand.fromCode()` recognizes `amex`, not `american_express`, and returns the non-null `Unknown` enum. `getDescription()` formats that enum's name, and `SavedPaymentMethodRowButton` exposes it as the content description with spaced digits. The icon and `PaymentSheetCardBrandFilter` already discard Unknown and fall back to the parsed card brand, explaining the correct icon and working brand filters. This is one description-fallback root cause.
