- Common21–28: customize colors/fonts/shapes/supported properties; layouts and interactions stay defined by Elements. Assigning configuration opts into that Element; configure only ones used. APIs may change before public preview.
- Android142–188: each Element Configuration.Appearance. Payment Element colorsLight and colorsDark; ThemeMode.Automatic follows system, options also force color mode. Example Colors.light()/dark() fields: primary, surface, component, componentBorder, componentDivider, onComponent, subtitle, placeholderText, onSurface, appBarIcon, error. Appearance applied to PaymentElement.Configuration then controller configuration.
- Android190–228: Shipping uses equivalent appearance property names; separate Colors objects for light/dark with primary/surface/component/border/onComponent/onSurface/error and ThemeMode.Automatic. Configuration `.title("Delivery address").buttonTitle("Save delivery address").appearance(appearance)`. Default addresses from CheckoutController.Configuration.Defaults, allowed countries from server shipping_address_collection, not appearance.
- Android230–249: Express wallet controls logo/brand colors/content. Theme Automatic and ButtonLayout maxColumns2/maxRows1 supported. Express pass already verified light/dark, row/one-cell, Plain button and personal Google Pay text limits. Avoid repeating those without new reason.
- Android251–276: Currency Selector labelContent can show currency code, formatted amount, or Stripe-selected representation. Example Appearance fields: contentVerticalPaddingDp(4f), cornerRadiusDp(12f), borderWidthDp(1f), borderColor #D8DEE4, background #F6F7F9, selectedBackground white, textColor #596780, selectedTextColor #1A1F36, textSecondaryColor #596780, dangerColor #DF1B41, fontResId(R.font.avenir_next), LabelContent.AMOUNT. Merchant must supply a valid font resource; absent placeholder app resources are not an SDK defect.

Verify supported properties against actual current API; existing API-drift report owns stale class/method/property names across guides. Exercise representative actual rendered Payment/Shipping/Currency appearance and state changes with valid configurations; compare exact colors/text/layout when meaningful, not subjective preference. Use AP handoff to obtain eligible currency UI. Capture and inspect screenshots, restore theme/accessibility/device settings. Temporary verification UI wiring is permitted by bug-bash scope but no fixes; archive reproduction and restore tracked source.
