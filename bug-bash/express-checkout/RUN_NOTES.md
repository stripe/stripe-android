## Documentation finding and rejected leads

- Express Android snippet's nonexistent CheckoutController is already the foundation report's root cause. Correcting the name still leaves `.fold` unavailable because configure returns OperationResult. [Compiler probe](compile_docs_probe.py) passed its assertions: [ActualExpressApi.kt](ActualExpressApi.kt) compiler exit0; [DocumentedExpressFold.kt](DocumentedExpressFold.kt) expected exit1/unresolved fold. [Output](docs-compiler-results.txt).
- Availability prose says ordered list of strings. Actual API is `Set<ExpressCheckoutElement.PaymentMethod>`; each value has `.type`. [DocumentedAvailableMethods.kt](DocumentedAvailableMethods.kt) models the prose's List<String> contract and fails with the expected type mismatch, while actual mapping compiles. It is explicitly a prose-contract probe, not a verbatim docs snippet. This evidence was folded into the same report, not a new finding.
- First compiler-control draft used Succeeded as an object instead of class; corrected the probe to `is Succeeded` before the successful run. Not an SDK finding.
- No missing Google Pay line items: factory, launcher, and real wallet UI all support them. Rejected.
- Card-only allowed types do not establish Link ineligibility: backend explicitly supplies LINK_CARD_BRAND configuration. Rejected as a local SDK bug.
- Link theme retains its brand-green appearance across configs; documentation gives wallet control over brand colors. Not reported.
- No independent payment-complete assumption from SDK callback alone. Both Link success cases have terminal poll proof. Retrieve returns `checkout_not_active_session` after completion; poll is the usable terminal endpoint. Initial standalone poll being pending before the settled callback is normal progression, not a failure.

- No Link bank-account funding, web-Link override, phone/OTP expiry/max-attempts matrix, device without wallets, rotation/process-death/result replay, concurrent confirm race, shipping/tax/adaptive-pricing or dynamic-total flow. Later specialists own those areas.
- Raw unconditional empty Express Content and exact runtime public availability-set values were not instrumented; UI guard/order and actual source mappings were inspected. No signed-webhook fulfillment asserted.
